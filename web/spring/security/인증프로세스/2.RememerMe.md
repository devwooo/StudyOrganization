# Spring Security RememberMe 정리

## 1. RememberMe란?

사용자가 로그인할 때 "로그인 상태 유지"를 선택하면, **세션이 만료되거나 브라우저를 닫아도 쿠키를 이용해 자동으로 재인증**해주는 기능이다.

- 세션은 브라우저를 닫으면 사라진다.
- 하지만 RememberMe 쿠키는 지정한 기간(기본 2주) 동안 살아있다.
- 그 쿠키를 이용해 다시 로그인 상태를 복구한다.

---

## 2. 핵심 구성요소 3인방

| 구성요소 | 역할 |
|----------|------|
| `RememberMeConfigurer` | 설정을 담는 클래스 (`.key()`, `.tokenValiditySeconds()` 등의 API 제공) |
| `RememberMeServices` | 토큰(쿠키)을 생성·검증·삭제하는 실제 서비스 |
| `RememberMeAuthenticationFilter` | 요청 시 쿠키를 보고 자동 인증을 수행하는 필터 |

---

## 3. 토큰 생성 / 삭제 시점 (로그인 필터와 연동)

RememberMe는 `UsernamePasswordAuthenticationFilter`와 함께 동작하며,
그 상위 클래스인 `AbstractAuthenticationProcessingFilter`의 훅을 통해 끼어든다.

| 이벤트 | 호출 메서드 | 동작 |
|--------|-------------|------|
| 로그인 **성공** | `RememberMeServices.loginSuccess()` | RememberMe 토큰 생성 후 쿠키로 전달 |
| 로그인 **실패** | `RememberMeServices.loginFail()` | 쿠키 삭제 |
| **로그아웃** | `LogoutFilter`와 연계 | 쿠키 삭제 |

- 토큰은 base64로 인코딩된 형태이며, hash 방식에서는 단방향 해시로 위조를 방지한다.
- 이 쿠키를 브라우저가 보관하다가, 이후 요청 때 다시 서버로 보내 자동 로그인이 이루어진다.

---

## 4. 설정 코드가 실행되는 순서 ⭐

```java
.rememberMe(remember -> remember
    .alwaysRemember(true)
    .tokenValiditySeconds(3600)
    .userDetailsService(userDetailsService())
    .rememberMeParameter("remember")
    .rememberMeCookieName("remember")
    .key("security"))
```

이 설정은 **두 단계**로 나뉘어 동작한다. 이것이 핵심 포인트.

### 1단계 — 람다 실행 (설정 수집)

- `http.rememberMe(...)`를 호출하는 **순간 람다가 즉시 실행**된다.
- 안에서 `RememberMeConfigurer`가 생성되고 `.key()`, `.tokenValiditySeconds()` 등이 연달아 호출된다.
- 하지만 이 메서드들이 하는 일은 실제 동작이 아니라 **필드에 값을 저장하는 것뿐**이다.

```java
public RememberMeConfigurer<H> key(String key) {
    this.key = key;   // 그냥 필드에 담아둠
    return this;
}
```

- 이 시점엔 아직 `RememberMeAuthenticationFilter`도, `RememberMeServices`도 만들어지지 않는다. **값만 모아둔 상태.**

### 2단계 — `init()` / `configure()` (실제 조립)

- 나중에 `http.build()`가 실행될 때 프레임워크가 모든 configurer의 `init()` → `configure()`를 차례로 호출한다.
- 바로 이 `configure()` 단계에서 **저장해둔 key 등을 꺼내** 실제 `RememberMeServices`와 `RememberMeAuthenticationFilter`를 만들어 필터체인에 등록한다.

### 타임라인 정리

```
http.rememberMe(람다)
   └─ 람다 즉시 실행
        └─ .key("security") 등 즉시 호출 → 필드에 값 저장만 함   ← 지금
   ...다른 설정들도 값만 수집...

http.build() 호출
   ├─ 모든 configurer.init()       실행
   └─ 모든 configurer.configure()  실행 → 저장된 key로 실제 객체 생성  ← 실제 사용
```

> **결론:** `.key()`는 `init()`/`configure()`보다 **먼저** 값만 세팅해두고,
> 그 값이 **실제로 쓰이는 건 `configure()` 시점**이다.
> (빌더 패턴 + 지연 초기화의 전형적인 구조)

## 5. 각 설정 API의 의미

| 설정 | 역할 | 비고 |
|------|------|------|
| `.alwaysRemember(true)` | remember 파라미터가 없어도 항상 쿠키 생성 | 보통은 false (체크박스 선택 시에만) |
| `.tokenValiditySeconds(3600)` | 토큰 유효 시간(초) | 예시는 1시간 |
| `.userDetailsService(...)` | 재인증 시 사용자 조회에 쓰는 서비스 | 필수 |
| `.rememberMeParameter("remember")` | 로그인 폼에서 기억하기 여부를 담는 파라미터명 | 기본값 `remember-me` |
| `.rememberMeCookieName("remember")` | 토큰을 저장하는 쿠키 이름 | 기본값 `remember-me` |
| `.key("security")` | 토큰 서명(식별)에 쓰는 시크릿 키 | **고정 필수**, 안 주면 랜덤 생성돼 재시작 시 쿠키 전부 무효화 |

## 6. RememberMeAuthenticationFilter 동작 흐름

이 필터는 **SecurityContext에 Authentication이 없을 때만** 동작한다.
즉, 아직 인증되지 않은 요청을 대상으로 쿠키 기반 자동 로그인을 시도한다.

```
client → GET /user
   │
   ▼
RememberMeAuthenticationFilter
   │
   ├─ Authentication != null ?
   │      └─ Y → chain.doFilter()  (이미 인증됨, 그냥 통과)
   │
   └─ N → RememberMeServices.autoLogin()
             │  (클라이언트 쿠키 ↔ 서버 저장 쿠키 비교, 일치하면 토큰 생성)
             ▼
        RememberMeAuthenticationToken (UserDetails + Authorities)
             │
             ▼
        AuthenticationManager
             │
             ├─ 인증 성공(Y)
             │     ▼
             │  RememberMeAuthenticationToken
             │     → SecurityContextHolder 에 설정
             │     → SecurityContextRepository (세션에 저장)
             │     → ApplicationEventPublisher (인증 성공 이벤트 게시)
             │
             └─ 인증 실패(N)
                   ▼
              RememberMeServices.loginFail()
                   → remember-me 쿠키 삭제
```

---

## 7. RememberMeServices 구현체 두 가지

| 구현체 | 방식 | 특징 |
|--------|------|------|
| `TokenBasedRememberMeServices` | 메모리 방식 | 쿠키 자체에 정보를 담고 해시로 보호. 별도 저장소 불필요하나 쿠키 탈취에 상대적으로 취약. (데모/간단한 앱) |
| `PersistentTokenBasedRememberMeServices` | DB 등 영구 저장소 방식 | 토큰을 저장하고 로그인마다 갱신(rotation). 탈취 탐지·무효화 가능. **실무 권장** |

> 두 방식 모두 사용자 정보를 조회하기 위한 `UserDetailsService`가 필요하다.

---

## 8. 한 줄 요약

> RememberMe는 **로그인 시 쿠키를 만들어 두고(loginSuccess) → 세션이 죽은 뒤 요청이 오면 그 쿠키를 필터가 검증해(autoLogin) → 통과하면 SecurityContext에 인증을 채워 넣는** 자동 재인증 기능이며,
> 설정은 `configure()` 시점에 실제 필터·서비스로 조립된다.
