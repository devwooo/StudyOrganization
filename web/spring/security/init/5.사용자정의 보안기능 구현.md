# Spring Security 설정 정리

## 기본 구성 절차

1. 설정 클래스에 `@EnableWebSecurity`를 선언한다.
   (Spring Boot에서는 `SecurityFilterChain` 빈만 등록하면 자동으로 켜지므로 생략 가능)
2. 하나 이상의 `SecurityFilterChain` 타입 빈을 정의한다.
3. 빈 안에서 `HttpSecurity`를 주입받아 **인증 API / 인가 API**를 설정한다.
4. `http.build()`로 체인을 완성해 반환한다.

---

## 기본 예시

```java
@EnableWebSecurity
@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
            .formLogin(Customizer.withDefaults());
        return http.build();
    }
}
```

- `SecurityFilterChain` 빈 정의 + `HttpSecurity` 의존성 주입
- 반환 타입은 `SecurityFilterChain`, 실제 객체는 `DefaultSecurityFilterChain`

---

## 인증 API (Authentication)

`HttpSecurity`에 인증 관련 설정을 건다.

| API | 역할 |
|---|---|
| `http.formLogin()` | 폼 기반 로그인 |
| `http.httpBasic()` | HTTP Basic 인증 |
| `http.rememberMe()` | 로그인 유지(자동 로그인) |
| `http.logout()` | 로그아웃 처리 |
| `http.csrf()` | CSRF 보호 설정 |
| `http.sessionManagement()` | 세션 정책(생성/동시세션 등) |
| `http.exceptionHandling()` | 인증/인가 예외 처리 |
| `http.addFilter(...)` | 커스텀 필터 추가 |

## 인가 API (Authorization)

**매처(어떤 요청)** 와 **규칙(누구에게 허용)** 이 짝을 이룬다.
하나의 매처에는 하나의 규칙만 붙는다.

```java
http.authorizeHttpRequests(auth -> auth
        .requestMatchers("/admin").hasRole("USER")   // 매처 → 규칙
        .requestMatchers("/public").permitAll()
        .anyRequest().authenticated()                // 나머지 전부
);
```

### 매처 (어떤 요청인지)

| 매처 | 의미 |
|---|---|
| `requestMatchers("/admin")` | 특정 경로 지정 |
| `anyRequest()` | 위에서 안 걸린 나머지 전체 |

### 규칙 (접근 권한)

| 규칙 | 의미 |
|---|---|
| `permitAll()` | 모두 허용 (인증 불필요) |
| `authenticated()` | 인증된 사용자만 |
| `fullyAuthenticated()` | 완전 인증(rememberMe 제외)만 |
| `hasRole("USER")` | 특정 롤 보유자만 |
| `access(...)` | 커스텀 표현식으로 판단 |
| `denyAll()` | 모두 거부 |

> 주의: `requestMatchers().hasRole().permitAll()` 처럼 규칙을 연속으로 붙일 수 없다.
> 매처 하나당 규칙 하나가 원칙이며, 위에서 아래 순서로 먼저 매칭된 규칙이 적용된다.

## 사용자 추가 설정

### 1. application.yml 방식

```yaml
spring:
  security:
    user:
      name: user
      password: 1111
      roles: USER
```

- 가장 간단하지만 **단일 사용자**만 정의 가능 (테스트/데모용)

### 2. Java 설정 클래스 방식

```java
@Bean
public UserDetailsService userDetailsService() {
    UserDetails user = User.withUsername("user")
            .password("{noop}1111")   // {noop} = 암호화 없음(평문)
            .roles("USER")
            .build();
    return new InMemoryUserDetailsManager(user);
}
```

- 여러 사용자 정의 가능, 로직 커스터마이징 유연
- `{noop}`은 평문 비밀번호 표시 → 실무에서는 `BCryptPasswordEncoder` 등 사용 권장

---

## 핵심 요약

- **@EnableWebSecurity** → 보안 인프라 활성화 (Boot에선 생략 가능)
- **SecurityFilterChain 빈 + HttpSecurity** → 인증/인가 설정의 진입점
- **인증 API** → "어떻게 로그인하나" (formLogin, httpBasic, rememberMe ...)
- **인가 API** → "누가 무엇에 접근 가능한가" (매처 + 규칙)
- **UserDetailsService** → "사용자 정보를 어디서 가져오나"
