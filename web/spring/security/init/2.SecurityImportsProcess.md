# Spring Boot 보안 Auto-Configuration 흐름 정리

## 로딩 흐름

```
@SpringBootApplication
  └─ @EnableAutoConfiguration
       └─ AutoConfigurationImportSelector
            └─ [읽음] META-INF/.../AutoConfiguration.imports
                 └─ SecurityAutoConfiguration  (@AutoConfiguration, 조건: DefaultAuthenticationEventPublisher 존재)
                      └─ @Import({
                            SpringBootWebSecurityConfiguration.class,   → 조건: SERVLET 웹앱
                            SecurityDataConfiguration.class             → 조건: SecurityEvaluationContextExtension 존재
                         })
```

---

## SpringBootWebSecurityConfiguration

| 중첩 클래스 | 한 줄 요약 |
|---|---|
| **WebSecurityEnablerConfiguration** | 개발자가 `@EnableWebSecurity`를 직접 안 붙였을 때, 대신 켜서 보안 인프라를 점화하는 클래스. |
| **SecurityFilterChainConfiguration** | 개발자가 만든 `SecurityFilterChain`이 없을 때, 기본 보안 체인(전체 인증 + formLogin + httpBasic)을 깔아주는 fallback 클래스. |

---

## 핵심 요약
- **WebSecurityEnablerConfiguration** → 판을 깔고 (보안 인프라 점화)
- **SecurityFilterChainConfiguration** → 그 위에서 뛴다 (기본 체인 정의)

두 클래스 모두 **"개발자가 직접 하지 않았을 때만"** 동작하는 fallback → 사용자 설정이 있으면 조용히 물러남.
