# Spring Security 빈 생성 흐름 정리

## HttpSecurityConfiguration

```java
@Bean(HTTPSECURITY_BEAN_NAME)
@Scope("prototype")
HttpSecurity httpSecurity() { ... }
```

- `HttpSecurity`를 **prototype 스코프**로 등록 → 요청될 때마다 새 인스턴스 생성
  (`build()`는 한 번만 호출 가능하고, 체인마다 자기 `HttpSecurity`가 필요하므로)
- `build()` → ... → `performBuild()` → **`DefaultSecurityFilterChain` 객체를 생성해 반환**
    - ※ `performBuild()`는 객체를 반환할 뿐, 이 객체가 "빈"으로 등록되는 것은
      `@Bean` 메서드의 반환값으로 컨테이너에 올라갈 때다.

### `http.build()`가 호출되는 위치

| 경우 | 어디서 `http.build()` | 생성되는 빈 이름 |
|---|---|---|
| **사용자 정의 X** | `SecurityFilterChainConfiguration.defaultSecurityFilterChain(...)` | `defaultSecurityFilterChain` |
| **사용자 정의 O** | 개발자가 만든 설정 파일의 `@Bean` 메서드 | 개발자가 지정한 메서드 이름 |

- 어느 쪽이든 반환 타입은 `SecurityFilterChain`, 실제 객체는 `DefaultSecurityFilterChain`.

## WebSecurityConfiguration

### 1. WebSecurity 객체 생성

```java
@Autowired(required = false)
public void setFilterChainProxySecurityConfigurer(
        ObjectPostProcessor<Object> objectPostProcessor,
        ConfigurableListableBeanFactory beanFactory) throws Exception {
    ...
    // objectPostProcessor.postProcess(new WebSecurity(...)) 로 WebSecurity 생성·후처리
}
```

- 이 세터 내부에서 **`WebSecurity` 객체가 생성**된다.

### 2. SecurityFilterChain 수집 (타입 기준 주입)

```java
@Autowired(required = false)
void setSecurityFilterChains(List<SecurityFilterChain> securityFilterChains) {
    this.securityFilterChains = securityFilterChains;
}
```

- **`SecurityFilterChain` 타입인 빈을 전부 모아 `List`로 주입**한다.
  (파라미터 이름이 아니라 **타입** 기준. 빈 이름은 무관)
- 필드 초기값 `emptyList()`는 방어용 기본값이고, 이 세터가 실제 값으로 교체한다.
- 주입(세터 호출)은 아래 `@Bean` 메서드 실행보다 **항상 먼저** 일어난다.

### 3. springSecurityFilterChain 빈 = FilterChainProxy

```java
@Bean(name = AbstractSecurityWebApplicationInitializer.DEFAULT_FILTER_NAME)
public Filter springSecurityFilterChain() throws Exception {
    ...
    return this.webSecurity.build();   // >> FilterChainProxy
}
```

- `webSecurity.build()`가 실행되면:
    - `WebSecurity`가 들고 있던 `securityFilterChains`(각 `SecurityFilterChain`)를
      **`FilterChainProxy` 생성자에 전달**하여 `FilterChainProxy` 객체를 만든다.
- 즉 **`springSecurityFilterChain`이라는 빈 이름으로 `FilterChainProxy`를 생성**한다.
- 이후 `FilterChainProxy`가 요청 URL에 맞는 `SecurityFilterChain`을 골라
  그 안의 필터들을 실행한다. (HttpSecurity가 만든 체인의 filter를 사용)

## 전체 그림

```
[서블릿 컨테이너]
     │  모든 요청이 하나를 거침
     ▼
springSecurityFilterChain (= FilterChainProxy, 타입: Filter)   ← WebSecurityConfiguration
     │
     │  내부에 List<SecurityFilterChain> 보유
     ├─ defaultSecurityFilterChain (SecurityFilterChain)        ← HttpSecurity.build()
     ├─ 사용자정의 chain A
     └─ 사용자정의 chain B
              │
              └─ 요청 URL에 맞는 체인 하나 선택 → 그 안의 필터 실행
```

## 핵심 요약

| 빈 이름 | 타입 | 실제 객체 | 개수 | 생성 위치 |
|---|---|---|---|---|
| `defaultSecurityFilterChain` | `SecurityFilterChain` | `DefaultSecurityFilterChain` | 여러 개 가능 | HttpSecurity.build() |
| `springSecurityFilterChain` | `Filter` | `FilterChainProxy` | 1개 | WebSecurity.build() |

- **HttpSecurity** → 개별 `SecurityFilterChain`을 만든다 (여러 개)
- **WebSecurity** → 그 체인들을 모아 하나의 `FilterChainProxy`로 묶는다 (하나)
