# DelegatingFilterProxy 등록 및 위임 흐름 정리

## SecurityFilterAutoConfiguration

```java
@AutoConfiguration(after = SecurityAutoConfiguration.class)
public class SecurityFilterAutoConfiguration {

    @Bean
    @ConditionalOnBean(name = DEFAULT_FILTER_NAME)   // springSecurityFilterChain
    public DelegatingFilterProxyRegistrationBean securityFilterChainRegistration(
            SecurityProperties securityProperties) {
        return new DelegatingFilterProxyRegistrationBean(DEFAULT_FILTER_NAME);
    }
}
```

- `@AutoConfiguration(after = SecurityAutoConfiguration.class)`
  → `SecurityAutoConfiguration`이 `springSecurityFilterChain`(= FilterChainProxy)을
  먼저 만든 **뒤에** 이 구성이 동작하도록 순서를 지정.
- `@ConditionalOnBean(name = DEFAULT_FILTER_NAME)`
  → `springSecurityFilterChain` 빈이 **존재할 때만** 이 등록 빈을 생성.
- `DelegatingFilterProxyRegistrationBean(DEFAULT_FILTER_NAME)`
  → 생성자로 넘긴 `DEFAULT_FILTER_NAME`(= `"springSecurityFilterChain"`)이
  **targetBeanName**으로 저장된다.

---

## getFilter() 가 호출되는 흐름

`DelegatingFilterProxyRegistrationBean`은 `ServletContextInitializer`다.
→ 웹서버(서블릿 컨텍스트)가 시작될 때 `onStartup()`이 호출되고,
그 호출 사슬 안에서 `getFilter()`가 불린다.

```
[웹서버 시작]
   └─ ServletContextInitializer.onStartup(servletContext)
        └─ DelegatingFilterProxyRegistrationBean.getFilter()
             └─ return new DelegatingFilterProxy(this.targetBeanName, getWebApplicationContext());
        └─ servletContext.addFilter(name, filter)   ← 서블릿 컨테이너에 등록
```

- `getFilter()`는 개발자가 직접 부르는 게 아니라,
  등록 과정에서 **"서블릿 컨텍스트에 넣을 필터 인스턴스가 필요할 때"** 자동 호출된다.
- 두 번째 인자 `getWebApplicationContext()`
  → 나중에 `targetBeanName` 빈을 **조회할 스프링 컨텍스트**를 미리 넘겨주는 것.

---

## DelegatingFilterProxy 의 역할

- `DelegatingFilterProxy`는 **서블릿 컨테이너에 등록되는 필터**다.
  (생성은 `getFilter()`에서, 등록은 `addFilter()`에서)
- 실제 보안 로직을 직접 처리하지 않고, **스프링 빈에게 위임(delegate)** 한다.
- 위임 대상은 `targetBeanName` = `"springSecurityFilterChain"` 빈.
- **첫 요청이 들어올 때(lazy)** 이 이름으로 빈을 조회해 위임한다.

```
서블릿 컨테이너
   └─ DelegatingFilterProxy  (targetBeanName = "springSecurityFilterChain")
        └─ [첫 요청 시] 스프링 컨텍스트에서 해당 빈 조회
             └─ FilterChainProxy 에게 위임
```

---

## FilterChainProxy 의 역할
- `springSecurityFilterChain`은 생성된 **`FilterChainProxy`의 빈 이름**이다.
- `DelegatingFilterProxy`로부터 요청을 위임받아 실제 보안 처리를 수행한다.
- **요청 URL 정보를 기준으로 적절한 `SecurityFilterChain`을 선택**하여 그 필터들을 호출한다.

---

## 전체 그림

```
[요청]
   │
   ▼
DelegatingFilterProxy  (서블릿 필터)
   │  targetBeanName = "springSecurityFilterChain" 으로 위임 (첫 요청 시 lazy 조회)
   ▼
FilterChainProxy  (= springSecurityFilterChain 빈)
   │  요청 URL 매칭
   ├─ /api/**   → SecurityFilterChain A → 필터 실행
   ├─ /admin/** → SecurityFilterChain B → 필터 실행
   └─ 그 외      → defaultSecurityFilterChain → 필터 실행
```

## 핵심 요약

| 구성요소 | 정체 | 역할 |
|---|---|---|
| `DelegatingFilterProxyRegistrationBean` | ServletContextInitializer | 웹서버 시작 시 필터 등록 |
| `DelegatingFilterProxy` | 서블릿 필터 | targetBeanName으로 스프링 빈에 위임 |
| `springSecurityFilterChain` | FilterChainProxy 빈 | 위임받아 보안 처리, URL별 체인 선택 |
| `SecurityFilterChain` | 개별 체인 (여러 개) | URL에 맞는 실제 보안 필터 묶음 |
